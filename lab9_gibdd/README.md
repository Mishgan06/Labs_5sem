## Модель доступа

| Пользователь | Назначение | Права |
|---|---|---|
| lr9_admin@localhost | Администратор gibdd | ALL только на gibdd.* через lr9_role_admin, GRANT OPTION; роль с ADMIN OPTION |
| lr9_analyst@localhost | Аналитик ДТП | SELECT cars, accidents, accident_cars через lr9_role_reader |
| lr9_inspector@localhost | Инспектор | Общая роль чтения; INSERT/UPDATE accidents и accident_cars напрямую; без DELETE |

Роль администратора назначена одному, роль чтения — двум пользователям. Два дополнительных аккаунта lr9_demo и lr9_empty созданы с ACCOUNT LOCK только для обязательных упражнений. Глобальные привилегии *.* демонстрируются на заблокированной lr9_demo, затем отзываются. Рабочим пользователям глобальные права не выдаются.

В положительном INSERT снимайте созданную строку до ROLLBACK, затем отдельно снимайте ноль после отката. Тесты привилегий не требуют отключения триггеров №8.

## Соответствие методичке

Создание пользователей и пользователя без прав; выдача ALL на *.*; USAGE с GRANT OPTION; системный просмотр mysql.user; выборочный GRANT; REVOKE ALL; минимум три пользователя; две роли с распределением 1 и 2; список ролей; доступ к gibdd с учётом ролей; самостоятельные SET DEFAULT ROLE и ALTER USER; консольные упражнения и Workbench.

Вместо публикации `SELECT * FROM mysql.user` используется выборка нужных полей той же таблицы без данных аутентификации. Форма из методички приведена и объяснена в отчёте. Глобальные флаги N не отражают все права через роли: для них нужны SHOW GRANTS ... USING и CURRENT_ROLE().

## Проверка

`verification.txt` — фактический протокол MySQL 8.0.46 в отдельном контейнере без опубликованных портов. Выполнены реальные входы всех трёх пользователей, положительные и отрицательные операции, назначения ролей, глобальные упражнения и полный отзыв демонстрационных прав. Исходные пять таблиц, функции и триггеры совпали с исходными SHA-256 после тестов. Дополнительно проверено выполнение листингов создания аккаунтов/ролей, извлечённых из отчёта, и итогового запроса доступа.

Управление аккаунтами не откатывается ROLLBACK: права отзывают через REVOKE. ROLLBACK используется только для временного INSERT инспектора. Остаток LR9_TEST откатывается в соединении инспектора, а не root. После штатных CREATE USER/GRANT/REVOKE не нужен FLUSH PRIVILEGES; интерфейс Workbench обновляется вручную.

Методичка и прежние отчёты использованы как источники задания, данных и оформления. Комплект подготовлен по запросу пользователя для той же базы и репозитория.

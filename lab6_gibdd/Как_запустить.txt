Порядок запуска в MySQL Workbench
1. Подключиться к серверу MySQL 8.0 с базой gibdd из работ № 4–5.
   Проверить наличие citizens, cars, accidents, accident_cars, sales.
   Данные не восстанавливать и не пересоздавать: исходная база уже должна быть.
2. Открыть 01_procedures.sql через File → Open SQL Script.
   Выполнить файл целиком кнопкой молнии без выделенного фрагмента.
   DROP PROCEDURE заменит только lr6_car_card и lr6_accidents_by_month.
3. Открыть 02_positive_tests.sql. Выполнять CALL и следующий SELECT
   в одном подключении: @-переменные принадлежат текущей сессии.
4. Открыть 03_negative_tests.sql. Выделять по одному CALL и выполнять.
   ERROR 1644 (45000) здесь — ожидаемый правильный результат.
5. После ошибки отдельно выполнить SELECT нужного @-итога и статуса.
   Для карточки: @lr6_status, @lr6_last_accident_count.
   Для сводки: @lr6_status, @lr6_last_year_total.
   Ожидаются ERROR и NULL. Не следует читать итог другой процедуры
   как результат текущего вызова.

Ожидаемые результаты
CALL gibdd.lr6_car_card(1): Lada Vesta, Петрова Мария, 2 ДТП.
CALL gibdd.lr6_car_card(9): Ford Focus, Новикова Ольга, 0 ДТП.
CALL gibdd.lr6_accidents_by_month(2025): 12 строк; август — 1,
сентябрь — 2, октябрь — 2, остальные месяцы — 0; итог — 5.
2024, 1901, 2155: по 12 нулевых строк, итог — 0.
Некорректный ID, неизвестный ID и недопустимый год вызывают SIGNAL 45000.
Если ваша база отличается от контрольного набора, числа будут другими.

Скриншоты для сдачи по методичке (с. 131–133)
В отчёте использована схема Workbench из пятой работы и фактические
протоколы локальной проверки. Протоколы CLI не выдаются за скриншоты
Workbench. Для выполнения требования преподавателя о скриншотах:
1. Открыть EER Diagram базы; расширить блоки до полных названий полей,
   расположить пять таблиц без пересечения связей. Заменить рисунок 1.
2. Выполнить запрос information_schema.ROUTINES из раздела 5 отчёта;
   сфотографировать запрос и Result Grid. Заменить рисунок 4.
3. Снять CALL lr6_car_card(1) и CALL lr6_car_card(9) с результатом.
4. Снять CALL lr6_accidents_by_month(2025) со всеми 12 месяцами и
   SELECT @lr6_status, @lr6_last_year_total (в том же соединении).
5. Снять результат для 2024 года и допустимых граничных годов.
6. Поочерёдно снять ошибочные вызовы из 03_negative_tests.sql
   с текстом вызова и диагностикой в Action Output.
   Нужно показать обе ошибки карточки: неверный ID и отсутствующий ID;
   для сводки — NULL и год вне диапазона.
7. Вставить изображения в раздел 6 и обновить подписи и ссылки на рисунки.
   Заменить пояснение о необходимости добавления снимков текстом
   о фактическом выполнении в вашем Workbench после проверки.

Процедуры не изменяют пять базовых таблиц. Сводка записывает только
собственную временную таблицу и удаляет её после выполнения.
Сессионные пользовательские @-переменные не являются настройками
@@GLOBAL сервера. Их область действия пояснена в отчёте.

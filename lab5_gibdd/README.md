Титульный лист сохранён без изменений из предыдущего отчёта, включая прежний номер № 3 и тему. Основная часть посвящена лабораторной № 5.

Сначала выполните `00_check_database.sql`. Не создавайте и не заполняйте базу заново, если исходная `gibdd` из ЛР № 4 уже есть. Ожидается 40 записей: 10 граждан, 10 автомобилей, 5 ДТП, 10 участий и 5 продаж.

## Соответствие методичке, подраздел 6.4, с. 102–103

| Требование | Файл / раздел |
|---|---|
| Схема всех таблиц и связей | Рисунок 1 |
| Однотабличная выборка WHERE | `01_where.sql`, листинг 1, рисунок 2 |
| Первая многотабличная выборка с WHERE, GROUP BY, ORDER BY | `02_join_group_owners.sql`, листинг 2, рисунок 3 |
| Вторая многотабличная выборка с WHERE, GROUP BY, ORDER BY; дополнительно HAVING | `03_join_group_accidents.sql`, листинг 3, рисунок 4 |
| Первый отдельный агрегатный запрос | `04_aggregate_prices.sql`, листинг 4, рисунок 5 |
| Второй отдельный агрегатный запрос | `05_aggregate_months.sql`, листинг 5, рисунок 6 |
| UPDATE с условием | `06_update_rollback.sql`, листинг 6, рисунки 7–9 |
| DELETE с условием | `07_delete_rollback.sql`, листинг 7, рисунки 10–12 |
| EXPLAIN | `08_explain.sql`, листинг 8, рисунок 13 |
| Пояснения, формулировки задач, расширенный вывод, источники | В отчёте |

`UPDATE` и `DELETE` действительно выполняются, но затем отменяются через `ROLLBACK`. Для съёмки до/после выполняйте части по инструкции в одном соединении. Таблицы должны использовать InnoDB. Не выполняйте COMMIT и DDL внутри учебных транзакций.

Инструкция содержит пять настоящих снимков из вашей ЛР № 4 как ориентиры интерфейса, а не как результаты новой работы. Новые результаты нужно снять в своём Workbench и вставить в отчёт. Размещение всех 13 снимков указано по номерам.

Все восемь запросов проверены на MySQL 8.0.46 с `ONLY_FULL_GROUP_BY` и `SQL_SAFE_UPDATES=1`. После каждого файла все значения всех строк пяти таблиц совпали с исходными. Фактический текстовый вывод находится в `Результаты_проверки_SQL.txt`.

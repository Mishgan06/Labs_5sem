# Формулы и контроль показателей

Датасет: dtp_spb. Воркбук по методичке: «Практическая работа 3».

## Пол участника ДТП
```text
IF ISNULL([participant_gender])
THEN 'Не указан'
ELSE [participant_gender]
END
```
Обрабатывается NULL. Пустая строка и строка из пробелов — отдельные случаи, которые надо проверить в источнике.

## Стаж водителя (отображение)
```text
IF ISNULL([participant_years_of_driving_experience])
THEN 'Не указан'
ELSE STR([participant_years_of_driving_experience])
END
```
STR нужен для одинакового строкового типа обеих ветвей. Исходное числовое поле стажа сохраняется для количественного анализа. Пропуск не заменяется нулевым стажем.

## Геоточка
```text
GEOPOINT([latitude], [longitude])
```
latitude — широта, longitude — долгота. Исходные числовые геополя не нужно превращать в геоточки по отдельности.

## Количество ДТП
```text
COUNTD([accident_id])
```
Название поля: Количество ДТП. Количество строк, автомобилей или участников не равно количеству событий.

## Временная иерархия
```text
DATEPART([datetime], "month")
DATEPART([datetime], "dayofweek")
DATEPART([datetime], "hour")
```
Имена: Месяц ДТП, День недели ДТП, Час ДТП.
Иерархия: Месяц ДТП → День недели ДТП → Час ДТП.
В строке "hour" нет пробела — в методичке он случайно появился. Используйте прямые кавычки.
Если в данных несколько лет, группировка по номеру месяца объединяет все январские записи и т. д.; это сезонный профиль, а не календарный тренд по месяцам разных лет.

## Погибшие и пострадавшие
Только если одна строка соответствует одному ДТП и численности заданы на событие:
```text
SUM([dead_count])
SUM([injured_count])
```
Первый показатель — число погибших людей, а не количество ДТП с летальным исходом.
Для числа событий с погибшими используется другой показатель:
```text
COUNTD_IF([accident_id], [dead_count] > 0)
```

COUNTD([injured_count]) не считает пострадавших людей: он считает разные значения численности (например, 0, 1 и 2). Если в источнике нет идентификатора человека, число уникальных пострадавших людей нельзя строго подтвердить по одному injured_count. Корректное название суммарного показателя: «Количество пострадавших по данным ДТП».

Если accident_id повторяется по участникам/машинам, простая SUM может завысить число людей. Сначала проверьте зерно и согласованность repeated dead_count/injured_count. Для аддитивных показателей нужна таблица на уровне одного ДТП; не используйте SUM(DISTINCT injured_count) — она тоже неверна. Решение с отдельной таблицей событий согласуется с преподавателем, если исходный датасет устроен по участникам.

## Семь чартов
1. Карта: Геоточка → Точки с кластеризацией; фильтр СЛОЯ: категория = «Наезд на велосипедиста»; подписи — Количество ДТП.
2. ДТП по регионам: Y=region, X/подписи/сортировка↓=Количество ДТП.
3. Погибшие по регионам: копия второго, X/подписи/сортировка↓=SUM(dead_count) после контроля зерна.
4. Линейная динамика: X=иерархия; Y=Количество ДТП; Y2=SUM(dead_count); подписи=Measure Values.
5. Световые условия: Y=light, X/подписи/сортировка↓=Количество ДТП.
6. Индикатор ДТП: COUNTD(accident_id).
7. Индикатор пострадавших: корректная сумма injured_count по событиям, не COUNTD численности.

Селекторы: region, фактическое поле категории ДТП, фактическое поле состояния дороги, light. Все четыре — в верхней строке.

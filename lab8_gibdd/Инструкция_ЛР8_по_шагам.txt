Шаг 5. Создай триггеры
Открой 01_triggers.sql. До запуска убедись, что тестовые транзакции не открыты. Выполни весь файл, включая USE, DROP, DELIMITER и все CREATE. Установочный файл пересоздаёт только три триггера lr8_bi_accident_date, lr8_bu_car_year, lr8_bd_last_participant. Процедура № 6 и функции № 7 сохраняются.
DDL-команды CREATE и DROP не откатываются вместе с тестовыми записями: установку выполняй отдельно от START TRANSACTION. Установка оставляет триггеры в базе и включает проверки для последующих операций. Обнови SCHEMAS. Триггеры вызываются автоматически при INSERT, UPDATE и DELETE; CALL или SELECT имени триггера не применяются.

Шаг 6. Список триггеров — рисунок 2

На рисунке 2 должны быть три имени, события INSERT/UPDATE/DELETE, момент BEFORE и таблицы accidents/cars/accident_cars. Дополнительные триггеры из других работ допустимы, но проверь, что они не меняют ожидаемые результаты. Сними запрос и Result Grid, вставь в рамку 2.

Как выполнять тесты
START TRANSACTION начинает транзакцию; ROLLBACK отменяет тестовые изменения записей. Выполняй тесты последовательно в одной вкладке соединения. Не нажимай COMMIT или Apply для сохранения временных данных. Переменные с @ и LAST_INSERT_ID() относятся к текущему соединению.
В положительных сценариях выполняй один блок целиком до его последнего SELECT. В отрицательных файлах выполняй A, B и C отдельно: A — подготовка; B — один оператор с ожидаемой ошибкой; C — проверка состояния и ROLLBACK. Workbench может остановить файл на ошибке и не выполнить оставшийся ROLLBACK автоматически. После каждого отрицательного теста обязательно выдели блок C и запусти его отдельно. Ошибка триггера отклоняет текущий оператор, но не отменяет автоматически всю ранее подготовленную транзакцию.

Шаг 8. Ошибочный INSERT — рисунок 4
Открой 03_negative_insert.sql. A: выполни USE, START TRANSACTION и SET. B: выдели только INSERT с CURRENT_DATE()+INTERVAL 1 DAY и выполни. Ожидается Error Code: 1644, текст LR8: future accident date. Это запланированный отказ триггера, он не означает ошибку в установочном коде.
Сделай скриншот оператора и сообщения в Action Output для рамки 4. C: отдельно выполни SELECT rows_before/rows_after и ROLLBACK. Количество ДТП до и после не изменится, на исходной базе 5/5. Дата берётся с сервера, а не с часов компьютера пользователя. Триггер проверяет только дату: время суток не сравнивается.

Шаг 10. Ошибочный UPDATE — рисунок 6
Открой 04_negative_update.sql. A: выполни подготовку и SELECT year_before. B: отдельно выполни UPDATE cars SET releaseYear=2026 WHERE carId=1. Ожидается Error 1644: LR8: car newer than accident.
Сними UPDATE и ошибку в Action Output, вставь в рамку 6. C: отдельно запусти SELECT year_after_error и ROLLBACK. Год должен оставаться 2020. Вызов с годом 2026 отклоняется из-за ДТП 2025 года, а не из-за обычного CHECK диапазона YEAR: 2026 сам по себе входит в допустимый диапазон.

После ROLLBACK temporary_accidents_after_rollback=0.

Шаг 12. Ошибочный DELETE — рисунок 8
Открой 05_negative_delete.sql. A: выполни подготовку до комментария B. Она создаёт временное ДТП с одним участником. B: выполни только DELETE; ожидается Error 1644: LR8: last participant.
Сделай скриншот запроса и ошибки для рамки 8. C: отдельно запусти оставшийся блок. До ROLLBACK participants_after_error=1 — участник сохранился. Если что-то не получилось
Error 1644 с одним из трёх сообщений LR8 в отрицательных тестах ожидаем. Если он появился в положительном тесте — проверь исходные данные, дату сервера и выполнение правильного блока. Не отключай триггер ради получения нужного скриншота.
Error 1175 / Safe Updates: используй приведённые WHERE с ключами carId или (accidentId,carId); не удаляй WHERE. Для DELETE в комплекте заданы оба столбца составного ключа.
Error 1146 / Unknown column: проверь имена таблиц и полей базы из № 6–7. Должны существовать releaseYear, accidentDate, accidentId и carId с тем же регистром.
Error 1142 / TRIGGER command denied или 1419: у учётной записи не хватает прав для создания триггеров в данной конфигурации сервера. Передай преподавателю точный текст ошибки; глобальные настройки сервера комплект не меняет.
Error 1064 рядом с BEGIN или END: выполни весь 01_triggers.sql с DELIMITER в Workbench. Не выделяй только середину определения триггера.
Error 1452 при подготовке участников: автомобилей 1 или 2 нет в базе; сначала проверь исходный набор. Ошибку выдаёт внешний ключ, это не проверяемый DELETE-триггер.
Если у положительного DELETE participants_after получилось не 1 — проверь, что используешь @lr8_delete_id из того же блока и не выполняешь SQL в другом соединении.

Область реализации
Три триггера демонстрируют выбранные события, а не полную систему контроля всех изменений. Будущая дата проверяется при INSERT accidents; её изменение через UPDATE accidents данным триггером не проверяется. Год автомобиля проверяется при UPDATE cars, а не при добавлении новых участий. Последний участник защищён от DELETE accident_cars, но перенос строки через UPDATE accidentId требует отдельного правила. Тесты однопользовательские; для конкурентной работы нужны отдельная схема блокировок и проверки. Эти ограничения отражены в отчёте.

Короткий разбор для защиты
Триггер — сохранённая на сервере программа, которая автоматически выполняется при событии INSERT, UPDATE или DELETE связанной таблицы. BEFORE используется для отклонения изменения до записи строки. AFTER подходит, например, для журналирования уже прошедшего изменения; в работе требуется проверка, поэтому выбран BEFORE.
FOR EACH ROW означает запуск для каждой строки оператора. При INSERT доступны NEW, при DELETE — OLD, при UPDATE — и OLD, и NEW. Параметры вручную триггеру не передаются: значения он получает из изменяемой строки. Функции № 7 вызываются через SELECT, процедура № 6 — через CALL, триггеры № 8 — соответствующими командами изменения таблиц.
В INSERT сравнивается NEW.accidentDate с CURRENT_DATE(), то есть с датой сервера. В UPDATE оператор <> означает «не равно»; EXISTS отвечает на вопрос, найдено ли хотя бы одно противоречащее ДТП. JOIN связывает таблицы участия и происшествий по accidentId. SELECT 1 внутри EXISTS выбран потому, что важен сам факт наличия строки, а не её поля.
В DELETE локальная переменная v_count хранит COUNT(*) участников конкретного ДТП. При двух участниках удаление одного допустимо; при одном — отклоняется. RETURN здесь не нужен: это триггер, а не функция, возвращающая число. SIGNAL SQLSTATE '45000' создаёт исключение с заданным MESSAGE_TEXT; в MySQL оно отображается как Error 1644.
START TRANSACTION объединяет подготовку и изменение в транзакцию. ROLLBACK отменяет записи теста, COMMIT сохранил бы их. В тестах COMMIT не используется. LAST_INSERT_ID() получает идентификатор только что добавленной строки текущего соединения; переменная @ хранит его для следующих запросов в той же сессии. После переподключения такие переменные нужно задавать заново.

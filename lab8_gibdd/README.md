## Порядок выполнения

1. Прочитайте PDF-инструкцию.
2. Выполните `00_check_database.sql` и сверьте исходные данные.
3. Установите триггеры полным файлом `01_triggers.sql`.
4. Список триггеров для рисунка 2 — первый SELECT файла `06_list_and_final_check.sql`.
5. Положительные блоки `02_positive_tests.sql` — рисунки 3, 5, 7. Каждый блок заканчивается откатом и проверкой.
6. Отрицательные файлы `03_negative_insert.sql`, `04_negative_update.sql`, `05_negative_delete.sql` — рисунки 4, 6, 8. Выполняйте подготовку A, ошибочный оператор B, проверку и откат C **отдельно**. После ожидаемой ошибки Workbench может остановить файл: оставшийся блок с ROLLBACK нужно запустить вручную.
7. Финальные запросы `06_list_and_final_check.sql` — рисунок 9. Схема Workbench — рисунок 1.
8. Вставьте скриншоты, заполните фактические результаты и экспортируйте окончательный PDF отчёта.

## Триггеры

| Имя | Событие | Проверка |
|---|---|---|
| lr8_bi_accident_date | BEFORE INSERT accidents | Запрет будущей даты ДТП |
| lr8_bu_car_year | BEFORE UPDATE cars | Запрет года выпуска позже зарегистрированного ДТП автомобиля |
| lr8_bd_last_participant | BEFORE DELETE accident_cars | Запрет удаления последнего участника командой DELETE |

Все триггеры `FOR EACH ROW`; нарушение приводит к `SIGNAL SQLSTATE '45000'` / Error 1644. Новые таблицы не создаются. Пересоздаются только три одноимённых триггера. Процедура №6 и функции №7 не меняются.

## Проверка и данные

Код проверен на MySQL 8.0.46 в изолированной схеме `gibdd_lr8_test` с исходным дампом из `lab4_gibdd/04_gibdd_dump_tested.sql`; в проверочных копиях файлов заменено только имя схемы. Шесть основных положительных и отрицательных сценариев дали ожидаемые результаты. Дополнительно проверены сегодняшняя дата, UPDATE без изменения года, автомобиль без ДТП и отклонение удаления сразу всех участников одним оператором. Протокол — `verification.txt`.

После каждого теста хеши содержимого всех пяти таблиц совпали с исходными. ROLLBACK восстанавливает записи; AUTO_INCREMENT может иметь пропуски. Триггеры остаются установленными. Дамп №4 пересоздаёт таблицы: импортировать его следует только в отдельную учебную копию либо после резервного копирования; при наличии gibdd повторный импорт не требуется.

Правила действуют только на указанные события. Они не охватывают обход проверки изменением даты через UPDATE accidents, добавлением новых участий или переносом строки участия через UPDATE accidentId. Конкурентные изменения не тестировались; для них нужна отдельная схема контроля и блокировок.

Методичка и прошлые отчёты использованы как источники задания, структуры и оформления. Установка и загрузка комплекта выполняются по запросу пользователя.

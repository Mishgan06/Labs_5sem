Что получится
Две функции MySQL: lr7_simple_car_count(id) — число ДТП автомобиля; lr7_simple_year_count(year) — число ДТП за год с циклом по месяцам. Ошибка параметра возвращает -1. В готовый шаблон отчёта нужно вставить восемь собственных скриншотов. В SQL всё уже написано; перепечатывать код из отчёта не нужно.

Шаг 1. Скачай комплект
На GitHub открой папку lab7_gibdd. Проще скачать ЛР7_ГИБДД_комплект.zip кнопкой Download raw и распаковать. Открой Отчет_ЛР7_ГИБДД.docx в Word. PDF — предварительный просмотр, редактировать нужно DOCX. Проверь ФИО, группу, преподавателя на титульном листе; подпись, дату и оценку заполняют отдельно.

Шаг 2. Подключись к своей базе
Запусти MySQL Server и MySQL Workbench. Открой то же соединение, в котором делал №6. Слева в SCHEMAS нажми Refresh и найди gibdd. Двойной щелчок по gibdd делает её текущей. Сервер и Workbench — разные программы: одного открытого Workbench недостаточно, сервер должен работать.
Если gibdd отсутствует, восстанови учебную базу из работы №4: lab4_gibdd/04_gibdd_dump_tested.sql в этом же репозитории. Этот дамп пересоздаёт таблицы: импортируй его только в отдельную учебную копию либо после резервного копирования своей базы. Если gibdd уже есть, дамп НЕ нужен.

Шаг 3. Проверь исходные данные
File → Open SQL Script → 00_check_database.sql. Выполни файл целиком кнопкой молнии. Если ничего не выделено, молния выполняет весь файл; если выделен текст — только выделение. Результаты появятся в отдельных вкладках Result Grid, ошибки — в Action Output.
На исходных данных должно быть: citizens=10, cars=10, accidents=5, accident_cars=10, sales=5; за август 2025 — 1 ДТП, сентябрь — 2, октябрь — 2; автомобиль 1 — 2 ДТП, автомобиль 9 — 0. Если твоя база изменена, ожидаемые числа могут отличаться: сверяй с прямым COUNT, не подгоняй записи под отчёт. Проверь, что carId=999999 отсутствует; иначе для отрицательного теста выбери другой отсутствующий положительный id и исправь SQL и таблицу отчёта.

Шаг 4. Сделай скриншот схемы — рисунок 1
Database → Reverse Engineer → выбери своё соединение → Next → отметь gibdd → Next → выбери пять таблиц → Execute → Finish. Если уже есть модель из №6, можно открыть её. На EER Diagram расположи citizens, cars, accidents, accident_cars, sales так, чтобы были видны поля, ключи и все шесть связей; перетащи таблицы и точки перегиба линий, убери пересечения. У accident_cars должны быть составной PK (accidentId, carId) и две связи. Остальные: cars.ownerId → citizens.citizenId; sales.carId → cars.carId; sales.sellerId и sales.buyerId → citizens.citizenId. Если старый файл модели расходится с сервером, используй Reverse Engineer заново.
Сними экран с читаемой диаграммой. В отчёте замени рамку «ВСТАВИТЬ СКРИНШОТ 1» этим изображением; подпись под рамкой оставь.

Шаг 5. Создай функции
File → Open SQL Script → 01_functions.sql. Выполни ВЕСЬ файл, включая USE, DROP, DELIMITER и оба CREATE. Он пересоздаёт только две функции lr7_simple_car_count и lr7_simple_year_count, не меняет строки таблиц и процедуру №6. Имена совпадают с ранней простой версией №7 из папки lab6_gibdd/simple: прежние определения этих двух функций будут заменены. После выполнения слева обнови gibdd → Functions: появятся обе функции.
Не запускай один фрагмент между BEGIN и END. DELIMITER — команда клиента, необходимая для создания многострочного тела функции.

Шаг 6. Список функций — рисунок 2
Открой 02_tests_and_screenshots.sql. Выдели только SELECT сразу после комментария «Рисунок 2» и выполни. Если текущая база не выбрана, сначала выполни USE gibdd в начале файла. На экране должны быть запрос и Result Grid с двумя функциями (другие функции базы тоже допустимы), ROUTINE_TYPE=FUNCTION, DATA_TYPE=int, IS_DETERMINISTIC=NO, SQL_DATA_ACCESS=READS SQL DATA. Сохрани скриншот и вставь вместо рамки 2.

Шаг 7. Успешные вызовы по автомобилю — рисунок 3
Выдели вместе два SET и SELECT в блоке «Рисунок 3» и выполни. На исходной базе одна строка: car_id=1, accident_count=2, second_car_id=9, second_count=0. SET и SELECT выполняй в одной вкладке соединения: переменные @ относятся к сессии. На скриншоте должны быть видны команды SET, запрос и числа. Вставь в рамку 3.

Шаг 8. Ошибочные id — рисунок 4
Выдели SELECT из блока «Рисунок 4». Четыре столбца null_id, zero_id, negative_id, missing_id должны содержать -1. Это ожидаемый результат, а не сообщение об ошибке сервера. Показаны обе ранние проверки: неверная форма id и отсутствие записи с положительным id. Вставь скриншот в рамку 4.

Шаг 9. Успешные вызовы по году — рисунок 5
Выполни оба SET и SELECT из блока «Рисунок 5» вместе. Ожидается report_year=2025, accident_count=5, empty_year=2024, empty_count=0. Цикл выполняет 12 итераций и складывает месячные количества. Сделай скриншот с запросом и результатом, вставь в рамку 5.

Шаг 10. Границы диапазона — рисунок 6
Выполни SELECT из блока «Рисунок 6». Для 1901 и 2155 ожидаются 0 и 0: эти годы допустимы и в исходной базе не содержат ДТП. Вставь скриншот в рамку 6.

Шаг 11. Ошибочные годы — рисунок 7
Выполни SELECT из блока «Рисунок 7». Для NULL, 1900, 2156 ожидаются три значения -1. Здесь цикл не запускается, функция завершается ранним RETURN. Вставь скриншот в рамку 7.

Шаг 12. Независимая проверка — рисунок 8
Выполни SELECT из блока «Рисунок 8». Должны совпасть пары function_car_1/direct_car_1=2/2, function_car_9/direct_car_9=0/0, function_year/direct_year=5/5. Прямой запрос по датам проверяет итог цикла другим способом. Вставь скриншот в рамку 8. Если есть расхождение — сначала проверь выбранную базу, определения функций и данные; не пиши в отчёте о совпадении до его получения.

Шаг 13. Закончи отчёт
Замени все восемь рамок изображениями через Вставка → Рисунки. Выбери обтекание «В тексте», ширину до 16 см; сохрани пропорции. Удали текст-заглушку внутри рамки, а подписи рисунков сохрани. Снимки должны содержать SQL и читаемый Result Grid; один блок — один рисунок. Если шрифт мелкий, увеличь масштаб Workbench или обрежь лишние панели.
В разделе тестирования заполни последний столбец таблицы фактическими результатами. Замени пометку о статусе шаблона на своё описание выполненной проверки; при изменённых данных исправь числа и вывод. Обнови поля документа (Ctrl+A → F9), проверь переносы листингов, расположение подписей и номера страниц. Сохрани DOCX и экспортируй окончательный PDF. Текущий PDF из комплекта содержит рамки и не является отчётом с твоими результатами.

Если возникли ошибки
• Error 1049 / Unknown database gibdd: проверь сервер и наличие базы; для пустого сервера используй отдельную учебную копию из №4.
• Error 1146 / Table does not exist или Unknown column: выполни SHOW TABLES FROM gibdd и SHOW CREATE TABLE gibdd.accidents; нужны имена из №6, в том числе accidentDate и carId. Не меняй структуру основной базы наугад.
• Error 1305 / FUNCTION does not exist: выполни 01_functions.sql целиком, проверь USE gibdd и Action Output.
• Error 1064 возле CREATE или END: проверь, что открыт MySQL Workbench и выполнен полный файл с DELIMITER.
• Error 1418: файл уже содержит корректное READS SQL DATA. Убедись, что выполняешь актуальный полный файл. Не объявляй функцию DETERMINISTIC ради обхода ошибки: результат зависит от содержимого таблиц.
• Error 1419 / недостаточно прав при включённом binary log: нужны соответствующие права администратора или разрешённая администратором настройка log_bin_trust_function_creators. Передай преподавателю текст ошибки. Комплект сам не меняет глобальные настройки сервера. В среде проверки функции созданы администратором MySQL 8.0.46 с log_bin=ON и trust=OFF.
• NULL вместо параметра в результате: выполни соответствующий SET в том же соединении; после переподключения пользовательские переменные теряются.

Что сказать на защите
Функция вызывается через SELECT и возвращает одно скалярное значение оператором RETURN; процедура №6 вызывалась через CALL. Локальные переменные DECLARE существуют только во время вызова. Пользовательские @lr7_car_id и @lr7_report_year живут в текущем соединении и передаются функции как аргументы; в учебной терминологии это глобальные переменные по отношению к блоку. Это не общие для всех подключений настройки @@GLOBAL. -1 означает ошибку параметра, 0 — корректный запрос без ДТП. Количество участий автомобиля не показывает виновность. Годовая функция считает строки accidents, поэтому несколько автомобилей в одном ДТП не завышают число происшествий. WHILE завершается после 12 итераций благодаря увеличению v_month. READS SQL DATA описывает чтение таблиц, NOT DETERMINISTIC — зависимость результата от текущих данных.

ЛАБОРАТОРНАЯ РАБОТА № 4. ВАРИАНТ 13 «ГИБДД»
Пошаговая инструкция для MySQL Workbench

1. Что подготовлено

Отчет_ЛР4_ГИБДД.docx — отчет с готовым текстом, SQL-кодом и десятью местами для скриншотов. Титульный лист перенесен из вашей лабораторной № 3 без изменения текста и оформления. Поэтому на нем сохранены номер № 3 и прежняя тема — это сделано по вашей просьбе. В основной части указана лабораторная № 4.

00_schema_reference.sql — эталон структуры по таблицам из отчета № 3. Это не экспорт из вашего файла .mwb. Основной путь выполнения по методичке — экспорт собственной модели через Forward Engineer.
01_constraints.sql — пять дополнительных CHECK-ограничений; выполнить один раз после создания пустых таблиц.
02_insert_data.sql — согласованный набор из 40 записей; выполнить один раз в пустых таблицах.
03_checks.sql — запросы для скриншотов и дополнительной сверки.
04_gibdd_dump_tested.sql — готовый дамп, полученный и проверенный на отдельном сервере MySQL 8.0.46. Для собственного скриншота экспорта создайте свой дамп на шаге 10.
Результаты_проверки.txt — фактические результаты проверки SQL и восстановления.

Файлы SQL имеют кодировку UTF-8. Сведения о людях и паспортные данные вымышлены. В отчете 10 мест для скриншотов. Тексты и подписи рисунков уже подготовлены; результаты на ваших снимках должны соответствовать выполненным командам. Действия в вашем Workbench еще предстоит выполнить; чужие или сгенерированные скриншоты не использовались.

2. Подключитесь к учебному серверу

Откройте MySQL Workbench, в MySQL Connections выберите соединение с вашим локальным учебным MySQL Server. Workbench является клиентом: для исполнения SQL нужен работающий сервер. Если соединения нет, создайте Standard TCP/IP: hostname 127.0.0.1, port 3306, имя вашего пользователя; проверьте Test Connection. Пароль используйте свой, в отчете его не указывайте. Если сервер не установлен, установите MySQL Community Server 8.0 с официального сайта и запустите службу MySQL; далее используйте свое созданное подключение. Права пользователя должны позволять создавать схему, таблицы и загружать данные.

В новой вкладке SQL выполните:
SELECT VERSION();
SHOW DATABASES LIKE 'gibdd';

Нужен MySQL 8.0.16 или новее: только начиная с 8.0.16 CHECK действительно исполняется. Подготовленные файлы проверены на MySQL 8.0.46. MariaDB и старые версии MySQL для точного повторения не использовались.

Если gibdd уже существует, сначала выясните, есть ли в ней данные, и сохраните резервную копию. Не запускайте создание и заполнение поверх существующей работы. Самый простой безопасный вариант — отдельный учебный экземпляр MySQL без схемы gibdd. В предоставленных рабочих SQL-файлах нет команд удаления существующей базы. Ничего удалять для лабораторной не требуется.

3. Откройте модель и сделайте скриншот № 1

Выберите File → Open Model и откройте свой файл .mwb из лабораторной № 3. В методичке физический перенос предусмотрен после проверки модели преподавателем. Убедитесь, что открыта согласованная модель варианта 13, а не пример из пособия.

В модели должны быть схема gibdd и пять таблиц: citizens, cars, accidents, accident_cars, sales. Имена и типы полей сверяйте с отчетом № 3 и файлом 00_schema_reference.sql. Особенно важны ownerId, sellerId, buyerId и составной первичный ключ accident_cars(accidentId, carId). Для citizens.passport задайте UNIQUE. Механизм хранения — InnoDB, кодировка — utf8mb4. Для совместимости с проверкой можно выбрать utf8mb4_0900_ai_ci.

Проверьте шесть внешних ключей:
1) cars.ownerId → citizens.citizenId;
2) accident_cars.accidentId → accidents.accidentId;
3) accident_cars.carId → cars.carId;
4) sales.carId → cars.carId;
5) sales.sellerId → citizens.citizenId;
6) sales.buyerId → citizens.citizenId.

ON DELETE и ON UPDATE — NO ACTION. У accident_cars оба поля входят в составной PK; у остальных таблиц используется один автоинкрементный PK.

Откройте EER Diagram и разложите таблицы без пересечений линий. Удобное размещение: accidents слева сверху, accident_cars справа сверху, cars в центре, citizens слева от cars, sales под cars. Для двух линий sales → citizens задайте отдельные параллельные маршруты. Расширьте блоки таблиц так, чтобы все имена полей читались. Сохраните модель через File → Save Model.

СКРИНШОТ № 1: вся EER-диаграмма с пятью таблицами и шестью связями. Вставьте его в рисунок 1 отчета.

Если .mwb потерян: используйте File → Import → Reverse Engineer MySQL Create Script, выберите 00_schema_reference.sql и импортируйте все пять таблиц в новую модель. При необходимости добавьте EER Diagram, перенесите на нее таблицы, проверьте связи и сохраните модель .mwb. Это восстановление по вашему отчету, а не открытие исходного .mwb; перед переносом на сервер согласуйте восстановленную модель с преподавателем. Затем продолжайте обычный экспорт на шаге 4.

4. Сгенерируйте SQL из модели: скриншот № 2

На вкладке модели откройте меню File → Export → Forward Engineer SQL CREATE Script. Перед выбором команды сделайте снимок, чтобы на нем были видны модель и команда меню. Это СКРИНШОТ № 2, рисунок 2 отчета.

В мастере задайте файл gibdd_create.sql и папку сохранения. Включите создание схемы (Generate CREATE SCHEMA), если этот пункт присутствует в вашей версии. Не включайте Generate DROP SCHEMA и Generate DROP Statements. Все пять таблиц должны быть выбраны; пропуск создания внешних ключей (Skip creation of FOREIGN KEYS) должен быть выключен. Пройдите Next до просмотра SQL, проверьте наличие CREATE SCHEMA/CREATE DATABASE, USE gibdd и пяти CREATE TABLE, затем Finish.

5. Создайте БД: скриншот № 3

Вернитесь в SQL Editor подключенного сервера. File → Open SQL Script → gibdd_create.sql. Для выполнения всего файла снимите выделение текста и нажмите кнопку молнии Execute All / Selection (обычно Ctrl+Shift+Enter). Не ограничивайтесь кнопкой Execute Current Statement: она исполнит только один оператор.

Проверьте Action Output: все команды должны выполниться без ошибок. На панели Schemas нажмите Refresh, раскройте gibdd → Tables. Должны появиться citizens, cars, accidents, accident_cars и sales.

СКРИНШОТ № 3: раскрытая схема gibdd с пятью таблицами; желательно также виден успешный Action Output. Вставьте в рисунок 3.

Файл 00_schema_reference.sql можно исполнить непосредственно только как запасной путь, если мастер недоступен; это создаст проверенную структуру, но не заменит требуемый методичкой скриншот генерации из модели. Для обычной сдачи используйте шаги 3–5.

6. Добавьте CHECK-ограничения

Откройте 01_constraints.sql в SQL Editor. Выполните целиком один раз. Это дополнение к исходной модели: положительная мощность и скорость, неотрицательная стоимость, ненулевой год и разные продавец/покупатель. Если эти ограничения уже добавлены в экспортируемую модель, не создавайте их повторно; сверяйте их наличие запросом из 03_checks.sql.

В варианте нет атрибутов с закрытым списком значений: список из десяти тестовых марок не является ограничением предметной области. Поэтому искусственный CHECK brand IN (...) не нужен. В используемых CHECK проверяются допустимые диапазоны и стороны продажи.

7. Заполните все таблицы

Сначала убедитесь, что таблицы пусты. Откройте 02_insert_data.sql. Скрипт выполняется один раз целиком: он начинает транзакцию, вставляет записи в правильном порядке и завершает COMMIT. Если версия Workbench позволяет, включите остановку выполнения скрипта при первой ошибке (Stop Script Execution On Errors).

Нажмите Execute All / Selection без выделенного текста. Дождитесь завершения и проверьте отсутствие красных ошибок. Если появилась ошибка, остановите выполнение; в том же соединении выполните ROLLBACK; и выясните причину. Не повторяйте скрипт поверх успешно добавленных данных и не отключайте FOREIGN_KEY_CHECKS для обхода ошибки.

Ожидаемый состав: citizens — 10, cars — 10, accidents — 5, accident_cars — 10, sales — 5. Всего 40 записей. Продажи уже согласованы с текущими владельцами. Для этой лабораторной не нужны дополнительные триггеры.

8. Сделайте скриншоты заполненных таблиц № 4–8

Откройте 03_checks.sql. В разделе A выделяйте и выполняйте по одному запросу SELECT. Удобнее запускать каждый отдельно, чтобы не перепутать вкладки Result Grid. Для снимка увеличьте панель результатов, уберите лишние окна, подберите ширину столбцов; должны читаться все имена полей и записи. Не включайте пустую строку для добавления новой записи в подсчет результата.

СКРИНШОТ № 4: SELECT * FROM citizens ORDER BY citizenId; — 10 строк, 5 столбцов. Рисунок 4.
СКРИНШОТ № 5: SELECT * FROM cars ORDER BY carId; — 10 строк, 7 столбцов. Рисунок 5.
СКРИНШОТ № 6: SELECT * FROM accidents ORDER BY accidentId; — 5 строк, 6 столбцов. Рисунок 6.
СКРИНШОТ № 7: SELECT * FROM accident_cars ORDER BY accidentId, carId; — 10 строк, 2 столбца. Рисунок 7.
СКРИНШОТ № 8: SELECT * FROM sales ORDER BY saleId; — 5 строк, 5 столбцов. Рисунок 8.

Для таблицы accidents расширьте city и street: названия должны отображаться полностью. Для cars оставьте видимыми price и ownerId.

9. Проверьте согласованность

Выполните оставшиеся запросы раздела B файла 03_checks.sql. Количество записей — 10, 10, 5, 10, 5. Запрос сверки владельца с покупателем последней продажи должен вернуть 0 строк — это успешный результат. В списке внешних ключей должно быть 6 строк, CHECK — 5 строк с ENFORCED = YES. Все пять таблиц должны использовать InnoDB. Дополнительные скриншоты для этих запросов в отчете не требуются.

10. Экспортируйте собственный дамп: скриншоты № 9–10

Выберите Server → Data Export. Отметьте gibdd и все пять таблиц. Выберите Dump Structure and Data (структура и данные), а не только структуру или только данные. В методичке в названии есть опечатка «Date»; в интерфейсе нужен пункт Data.

Выберите Export to Self-Contained File, задайте папку и имя gibdd_lab4_dump.sql. Используйте существующую папку, доступную для записи. Например, создайте папку Lab4_GIBDD в Документах вашего пользователя и выберите ее через кнопку обзора. Включите Include Create Schema.

СКРИНШОТ № 9: настройки экспорта, видны схема gibdd, все пять таблиц, Dump Structure and Data, Self-Contained File, путь и Include Create Schema. Вставьте в рисунок 9.

Нажмите Start Export, дождитесь Export Completed. Если экспорт не завершился, файл не считается готовым. При ошибке несовместимости mysqldump укажите утилиту от той же версии MySQL Server в Edit → Preferences → Administration → Path to mysqldump Tool и повторите экспорт. Если ошибка сообщает Unknown table COLUMN_STATISTICS, в расширенных параметрах экспорта отключите column-statistics и повторите.

Откройте выбранную папку в Проводнике. Включите Показать → Расширения имен файлов. Щелкните адресную строку, чтобы был виден полный путь, а не только цепочка папок. Выделите gibdd_lab4_dump.sql; убедитесь, что размер файла ненулевой.

СКРИНШОТ № 10: файл дампа и полный путь в адресной строке Проводника. Вставьте в рисунок 10. Проверенный пример дампа уже есть в комплекте как 04_gibdd_dump_tested.sql, однако для подтверждения своей работы используйте собственный экспорт.

Альтернатива экспорту через GUI — командная строка с установленным mysqldump:
mysqldump -u root -p --default-character-set=utf8mb4 --single-transaction --no-tablespaces --set-gtid-purged=OFF --databases gibdd > gibdd_lab4_dump.sql
Команду запускают из папки, где нужно сохранить файл; вместо root при необходимости указывают своего пользователя. Пароль вводится только по запросу утилиты. Для варианта со скриншотами из отчета предпочтителен экспорт через Workbench.

11. Вставьте снимки в готовый отчет

Откройте Отчет_ЛР4_ГИБДД.docx в Word. В каждой серой рамке удалите текст-заполнитель и вставьте соответствующий скриншот через Вставка → Рисунки. Используйте обтекание «В тексте», сохранение пропорций и ширину не больше 16,5 см. Если изображение недостаточно читается, увеличьте его по высоте; переход на следующую страницу допустим. Не меняйте готовые подписи рисунков и не редактируйте SQL-код.

Титульник оставьте без изменений. Всего нужно заменить 10 заполнителей. Перед сохранением убедитесь, что надписи «МЕСТО ДЛЯ СКРИНШОТА» больше не остались, каждый рисунок имеет правильный номер и все таблицы читаются. Скрипты создания, ограничений и заполнения сохраните вместе с моделью .mwb и вашим дампом.

12. Что проверено при подготовке

SQL действительно выполнен на отдельном MySQL 8.0.46: создана структура по отчету № 3, добавлены 40 записей, выполнены SELECT всех таблиц. Проверены 6 внешних ключей, 5 CHECK, уникальный паспорт и составной PK. Восемь попыток нарушить ограничения отвергнуты с ожидаемыми ошибками. Дамп восстановлен на втором экземпляре MySQL; все значения 40 записей и ограничения совпали, отрицательные проверки повторены успешно.

Ваш файл .mwb и подключение к вашему серверу не предоставлялись. Поэтому открытие модели, генерацию кода и экспорт через ваш Workbench необходимо выполнить по этой инструкции и подтвердить собственными скриншотами. Формулировки отчета о проверке SQL относятся к фактически проведенной проверке подготовленных файлов, а не к действиям в вашем Workbench.
